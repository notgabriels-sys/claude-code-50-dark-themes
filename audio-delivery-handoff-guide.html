Guide / audio delivery QA

How to check a WAV delivery package before sending it.

A bounced folder can fail before anyone judges the music: wrong version, unclear format, missing alternate, broken archive, stale notes, or filenames that make the recipient guess. This guide is a practical preflight workflow for producers, engineers, labels and technical collaborators.

The boring failure is the expensive one.

A good mix can still arrive as a bad delivery. The recipient may not know which file is final, whether a stem starts at the same bar as the master, whether the archive contains the right revision, or whether the format was chosen from the actual brief. These are not glamorous problems, but they cost attention, trust and time.

The solution is not a bigger claim. It is a repeatable handoff ritual: confirm the brief, export intentionally, inspect the folder, listen in targeted places, package carefully, then send a short note that makes the delivery easy to understand.

Practical preflight workflow

01

Confirm the destination, not a mythical default.

There is no single correct WAV target for every situation. A mastering engineer, label archive, distributor upload, client approval and stem handoff can all need different things.

  • Name the recipient and purpose of the delivery.
  • Check the requested sample rate, bit depth, channel layout and file roles.
  • If the target is unknown, write the assumption clearly instead of hiding it.
02

Export from the approved session state.

Before exporting, make sure the session matches the decision you intend to send.

  • Confirm the approved mix, master, stem print or alternate version.
  • Check that muted tracks, automation, external effects and hardware returns are intentional.
  • Print from the correct start/end range, including intentional silence and tails.
03

Inspect the files as received objects.

Do not trust memory. Inspect the exported files, not the plan in your head.

  • Check file count, roles, names, duration, sample rate and bit depth.
  • Look for duplicate “final” versions, empty folders, temporary files and ambiguous names.
  • For stems, verify shared starts and naming patterns so reconstruction is not a puzzle.
04

Listen where technical checks are blind.

Preflight does not replace listening. It helps you aim attention at the places where export mistakes hide.

  • Listen to starts, endings, transitions, breakdowns, loudest moments, quiet sections and final tails.
  • Recheck risky edits, mutes, printed effects, fades and render boundaries.
  • If a stem package matters, rebuild the mix from the stems in a clean session when practical.
05

Package the delivery as the recipient will see it.

The final transfer is the real deliverable. A clean local folder is not enough if the ZIP or upload is wrong.

  • Create the final archive or transfer folder after cleaning the delivery contents.
  • Reopen the archive and check that it contains only the intended files.
  • Add a short delivery note and checksums when the package is important, large, repeated or archival.
06

Send context, not just files.

A concise note prevents the recipient from guessing what they received.

  • Name the artist/title/version/date.
  • List included assets and any known deviations from the brief.
  • Ask for receipt confirmation before anyone treats the package as the final source of truth.

Stop and clarify if...

  • there are several files claiming to be final,
  • the expected format was never actually specified,
  • the archive was never reopened after creation,
  • stems do not share a clear start point or role naming,
  • nobody listened to risky boundaries after export.

Useful delivery note

Hi — attached is the delivery package for [artist/title], version [version/date]. It contains [asset list]. Format is [sample rate / bit depth / channel layout] according to [brief or provisional assumption]. Known notes/deviations: [none / list]. Please confirm receipt before using this as the final delivery source.

Free checklist first, paid automation second.

The free checklist is enough to run the process manually. Audio Delivery Preflight CLI exists for repeated work: local folder inventory, technical evidence, delivery hygiene, reports and checksum workflow. It does not upload audio, rename files, master music, judge artistic quality or guarantee acceptance by a distributor or label.

audio-preflight scan /path/to/delivery --preset digital-release \
  --report-html /path/outside/delivery/preflight-report.html \
  --checksums /path/outside/delivery/SHA256SUMS.txt
