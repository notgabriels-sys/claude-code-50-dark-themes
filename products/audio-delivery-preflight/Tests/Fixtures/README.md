# Test fixtures

The automated suites create small, original fixtures inside per-test temporary directories. The committed `valid-digital-release` package is also generated entirely by `scripts/generate-valid-digital-release-fixture.swift`; it contains a one-second synthetic 440 Hz WAV, a generated solid-color PNG, and synthetic credits text. No customer delivery, commercial recording, artist master, account data, or private report belongs in this directory.

Generated fixtures cover:

- mono and stereo PCM WAV files;
- 16-bit and 24-bit PCM;
- AAC/M4A and trusted container identification;
- truncated and content-mismatched audio;
- PNG and JPEG artwork with controlled dimensions and alpha state;
- normal nested files, service files, symbolic links, special entries, and path-boundary races;
- exact and non-matching byte content;
- ready, warning, error, cancellation, and incomplete scan results; and
- stable, private HTML, JSON, and SHA-256 report output.

Run all generated-fixture checks from the product root:

```bash
swift test
```

The release-candidate verifier independently regenerates `valid-digital-release`, compares every generated byte with the committed fixture, runs the exact Digital Release CLI happy path, compares source SHA-256/size/fractional-mtime/mode before and after, compares the complete checksum manifest byte-for-byte, and checks measured properties with `afinfo` and `sips`:

```bash
scripts/verify.sh
```

Manual release-candidate validation may use a copied, non-sensitive real delivery in a temporary directory. Do not commit that delivery, its absolute path, or its reports.
